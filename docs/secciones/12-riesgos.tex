\section{Análisis de riesgos técnicos}

El análisis de riesgos del SGRA considera las dependencias entre servicios, la integridad de los datos y los posibles errores durante el despliegue y la recuperación.

Como antecedente se utiliza la práctica \href{https://github.com/Yukisan-uwo/FORM-AC-01-Analisis-de-Caso-Fallo-en-Sistema-Distribuido-Real} {FORM-AC-01}, en la que se analizó la caída de Cloudflare del 21 de junio de 2022.

El incidente se originó por una modificación incorrecta en el orden de reglas BGP. Las pruebas previas no detectaron el problema, el despliegue permitió que se propagara y algunas reversiones descoordinadas dificultaron la recuperación.

Estas situaciones se utilizan como antecedentes para identificar riesgos del SGRA. No significa que el proyecto haya sufrido los mismos fallos.

\subsection{Escala de valoración}

La probabilidad y el impacto se valoran cualitativamente mediante tres niveles:

\begin{itemize}
    \item \textbf{Baja (1):} ocurrencia poco probable
    o consecuencias limitadas.
    \item \textbf{Media (2):} ocurrencia posible
    durante la operación o integración, o
    afectación importante pero recuperable.
    \item \textbf{Alta (3):} ocurrencia probable
    o consecuencias graves para la continuidad,
    la integridad o el acceso al servicio.
\end{itemize}

Las valoraciones corresponden a estimaciones iniciales del diseño y deben revisarse con el equipo. No representan frecuencias estadísticas ni resultados experimentales.

\subsection{Relación con el incidente FORM-AC-01}

Los riesgos R1, R2 y R3 se relacionan directamente con las causas y dificultades de recuperación identificadas en la práctica FORM-AC-01.

\begin{itemize}
    \item \textbf{R1:} el cambio incorrecto en el orden de reglas BGP de Cloudflare demuestra cómo una configuración defectuosa puede interrumpir la comunicación. En el SGRA, una situación análoga podría producirse al modificar direcciones o rutas de servicios.

    \item \textbf{R2:} las pruebas previas y el despliegue escalonado del incidente no detectaron ni contuvieron adecuadamente el problema. Para el SGRA, esta lección justifica verificar los contratos antes de propagar cambios entre componentes.

    \item \textbf{R3:} durante la recuperación de Cloudflare, algunas reversiones interfirieron con correcciones anteriores. En el SGRA se propone coordinar las acciones de recuperación y comprobar la compatibilidad de las versiones.
\end{itemize}

Adicionalmente, R5 retoma la lección específica para el SGRA documentada en FORM-AC-01: una interrupción entre el registro de un refuerzo y el envío de su notificación puede provocar inconsistencias o duplicaciones.

Como medida de diseño se propone registrar de forma transaccional la operación y el evento pendiente de notificación. El envío posterior debe controlar los reintentos para evitar efectos duplicados.

\subsection{Relación con la implementación E1}

El riesgo R4 se relaciona con la comunicación síncrona REST/HTTP implementada durante E1.

Las pruebas manuales demostraron que, al detener el servicio académico, el servicio de refuerzos respondió con HTTP 503 y el código \texttt{SERVICIO\_ACADEMICO\_NO\_DISPONIBLE}.

Después de reiniciar el receptor, la consulta volvió a responder con HTTP 200 sin reiniciar el emisor.

El cliente HTTP incorpora tiempos de espera de un segundo para conexión y un segundo para lectura. Sin embargo, estas configuraciones no garantizan alta disponibilidad ni eliminan la dependencia entre los servicios.

Las medidas de despliegue escalonado, recuperación coordinada y notificaciones idempotentes son propuestas para las siguientes etapas del SGRA. No se consideran implementadas ni verificadas en el esqueleto de E1.

\subsection{Seguimiento de los riesgos}

Antes de ampliar la implementación, el equipo deberá revisar las valoraciones y mitigaciones con el arquitecto y el líder de desarrollo.

La validación incluirá pruebas de integración, revisión de configuraciones, comprobaciones de recuperación y pruebas de duplicación de operaciones cuando se implementen las funcionalidades correspondientes.
