\section{Arquitectura base: modelo C4}
\subsection{C4 nivel 1: contexto}
La Figura~\ref{fig:c4-contexto} delimita el SGRA y sus relaciones con personas y sistemas externos~\cite{atodiresei-c4-2024}. El estudiante solicita y consulta refuerzos; el docente decide, programa y registra sesiones; coordinación académica realiza seguimiento; administración gestiona cuentas y configuración; y el gestor de áreas de trabajo atiende reservas. El SGA simulado proporcionaría los datos académicos por API. SMTP apoya las notificaciones, Azure Blob Storage almacena los recursos de las sesiones y Groq se propone únicamente como apoyo a la validación del formulario de solicitudes de refuerzo.

\subsection{C4 nivel 2: contenedores}
La Figura~\ref{fig:c4-contenedores} distingue la aplicación web Angular, la API Spring Boot y PostgreSQL dentro del límite del SGRA. La SPA usa HTTP/JSON y sesión HTTP; la API accede a PostgreSQL mediante JPA/JDBC. Los módulos Java pertenecen a un mismo backend desplegable. La API consultaría al SGA simulado por HTTP/JSON, sin acceso directo a sus tablas, y se comunicaría con SMTP, Azure Blob Storage y Groq para las funciones de apoyo indicadas.
